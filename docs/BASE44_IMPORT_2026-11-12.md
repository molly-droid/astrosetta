## Operational tools

The original `import-base44.mjs` overwrites matching rows and does not suppress
welcome emails. Use the reconciliation tools for production overlap instead:

1. Capture a private snapshot using `reconcile-base44.mjs snapshot PRIVATE_DIR`
   and save DB trigger/job definitions, column metadata and password
   fingerprints. This import's `database-state.json` documents that checkpoint.
2. Apply `scripts/import/hold-migration-automation.sql` and verify the hold.
3. Install `scripts/import/import-batch-rpc.sql`. It grants execution only to
   service_role, rejects stale revisions and requires the email hold.
4. Prepare and inspect a plan with `buildPlan`; apply with
   `reconcile-base44.mjs apply PRIVATE_EXPORT_ROOT` only when the private root
   has the required `converted/` and `supabase-before/database-state.json`.
5. Run `verify-base44-import.mjs PRIVATE_EXPORT_ROOT`. This creates and removes
   only an isolated synthetic account and sends no emails.
6. Drop `public.apply_base44_import_batch(text,jsonb,jsonb)` after verification.
   This temporary RPC has already been removed from production.

The apply command refuses to overwrite its pre-apply backup. If interrupted,
inspect the private checkpoint and regenerate a plan from a fresh target
snapshot; do not blindly replay a stale plan. Install workspace dependencies
before using these tools; the Supabase SDK resolves from `apps/web`.
