**B-07 ✅ (really, this time).** The round-1 fix added an ascendant fallback

leave room for a button occupying the top 40px. Floating the column takes it
out of flow — the first lines wrap around it, the rest run full width.

## E. PF-06 measurement and plan (2026-10-17)

Production numbers from `ai_request_metrics` (14 days): every LLM task lands
at 10–15 ms per OUTPUT token (~90 tokens/s). `day-synthesis` is the worst —
avg 51.6s, 4,779 output tokens (n=14; an independent live profile measured
48.5s). Chart math is NOT the problem: chart-calculator averages ~400ms and
every moment is permanently cached in `ephemeris_cache`. The prompt and
output schema are byte-identical to Base44's (our only addition is the AI-04
STYLE_RULES, input-side); Base44 never names a model, so the one migration
variable is the model behind their InvokeLLM vs our claude-sonnet-5. Molly
has not called this a regression — PF items are "too slow", not "was faster".

Levers, in order:
1. **Streaming — SHIPPED.** `llm-task` takes `stream: true` and returns
   NDJSON (deltas + a final parsed `done` payload identical to the buffered
   path); `invokeLLM` grew an optional `onDelta`; the client falls back to
   the buffered call on any missing capability; the Daily Reading renders the
   overview as it arrives. Measured: first text at 3.0s vs 52s; total
   generation unchanged (51.5s). One task of 37 converted — month-topics
   (31s), pre-generate-synthesis (24s) and generate-calendar-synthesis (16s)
   are the next candidates.
2. **Cut output.** `personal_reading_core` is prompt-defined as an exact
   duplicate subset of `personal_reading` — the model writes those bullets
   twice. Derive it by filtering instead. Content change: Molly sees it
   first.
3. **Pre-generate the week** (extends the existing today-only cron). Closes
   B-23 and PF-05 properly. Cost/scope decision: Molly.
4. Optional: same prompt on a faster model (`LLM_MODEL` env swap),
   quality-checked side by side before committing.
